# Troubleshooting

Each entry lists a **symptom**, its **root cause**, and an actionable **fix**.

Attendees who fall behind can run `make catch-up MODULE=N` to converge idempotently to the verified end state of module `N-1`. Add `RESET=1` (`make catch-up MODULE=N RESET=1`) if an `ActorTemplate` (`sre-agent-v1..v4`) was created before saving `app/cmd/agent/main.go`: `RESET=1` deletes the broken template and its actors, rebuilds `cmd/agent` from the module's `solution/main.go`, and warms a clean Golden Snapshot.

## Setup and preflight

| Symptom | Cause | Fix |
|---|---|---|
| `make preflight` fails on `uniform-CPU node pools` | The cluster uses mixed-CPU `e2-*` nodes or unpinned `n1-*` / `n2-*` pools (`AUTOMATIC` CPU platform). Cross-worker `SNAPSHOT_FIDELITY_MEMORY` restores fail if an actor checkpoints on Intel and wakes on AMD (or an older microarchitecture). | Provision a uniform-CPU node pool (`c3-standard-4`, `n4-standard-4`, `n2-standard-4` with explicit `--min-cpu-platform`, or `n1-standard-4` with `--min-cpu-platform="Intel Skylake"` in Google Skills). For single-node or non-production smoke tests only, `ALLOW_MIXED_CPU_FOR_TEST=true make preflight` bypasses the gate with a warning. |
| `error: unknown command "ate" for "kubectl"` | `bin/kubectl-ate` was built by `make install-bg`, but `$PWD/bin` is missing from the current shell `PATH`. | Run `source scripts/env.sh` (or `export PATH="$PWD/bin:$PATH"`) from the repository root. |
| `kubectl ate` rejects `-o` output flag when extracting JSON fields | `kubectl-ate` `v1.0.0` supports only `-o table`, `-o json`, and `-o yaml`. | Pipe `-o json` into `jq`, for example `kubectl ate get actor inc-402 -a "$ATESPACE" -o json \| jq -r '.status.state'`. |
| `ko build` fails with `403 Forbidden` pushing to Artifact Registry | Docker credential helper is not configured for `${REGION}-docker.pkg.dev`, or Artifact Registry IAM has not propagated. | Run `gcloud auth configure-docker "${REGION}-docker.pkg.dev" --quiet` or re-run `make gcp`. |
| Golden Snapshot upload fails with `Unavailable` after running `make teardown ALL=1` and re-running `make gcp` | `ate-api-server` caches OAuth tokens for `ate-snapshot-transfer@${PROJECT_ID}.iam.gserviceaccount.com` in memory for ~1 hour. Deleting and recreating that service account changes its unique ID while `ate-api-server` still holds the old token source. | Restart the API server so it mints tokens against the recreated service account: `kubectl -n ate-system rollout restart deploy/ate-api-server && kubectl -n ate-system rollout status deploy/ate-api-server`. (`scripts/gcp-resources.sh` automates this when `ate-system` is present.) |
| `make publish-skill` pauses on `gcloud agent-registry` CLI calls on client-certificate workstations | On workstations with context-aware mTLS enabled, `gcloud agent-registry` dials `agentregistry.mtls.googleapis.com:443` and can stall if the endpoint rejects client certificates. | `scripts/publish-skill.sh` wraps CLI probes with `timeout 10` and `--http-timeout=8` before falling back to REST and direct `sre-gateway` bundle sync. Set `SKIP_GCLOUD_SKILL_REGISTRY=1 make publish-skill REV=v2` to sync directly to `sre-gateway` without waiting on the CLI probe. |

## Incident Actors and Golden Snapshots

| Symptom | Cause | Fix |
|---|---|---|
| `ActorTemplate` (`sre-agent-v1..v4`) never populates `goldenTag` or Golden Actor enters `CRASHED` | Either (1) both `WorkerPool/sre-workers` pods are already occupied by `RUNNING` actors, or (2) custom startup code inside `app/cmd/agent` dialed an outbound HTTP endpoint before `/readyz` returned `200 OK`. Temporary Golden Actors run with `GoldenEgressPolicy=off` (strict zero-egress default deny) until cloned into an Incident Actor with an `EgressPolicy`. | First check `kubectl ate get actors -a "$ATESPACE"` and suspend running actors (`kubectl ate suspend actor inc-402 -a "$ATESPACE"`) so a worker slot is free. Second, keep ADK runner and MCP discovery initialization inside `agentruntime.Server`'s lazy first-turn initializer rather than calling network APIs during container startup before `/readyz`. |
| Incident Actor state is `CRASHED` | The agent process exited non-zero or failed its port `80` `/readyz` wakeup probe on restore. | Inspect logs with `kubectl ate logs actor inc-402 -a "$ATESPACE"`. Roll back to the last valid snapshot with `kubectl ate revert actor inc-402 -a "$ATESPACE"`, or delete and recreate it via `kubectl ate delete actor inc-402 -a "$ATESPACE"`. |
| Code changes in `app/cmd/agent/main.go` do not appear on `inc-402` | `ActorTemplate` Golden Snapshots and an `Actor`'s `actorTemplate` reference are immutable. Rebuilding the image alone does not mutate an existing template or running actor. | Run `make catch-up MODULE=N RESET=1` for the next module, or register a new template revision, update `DEFAULT_ACTOR_TEMPLATE` via `make gateway`, and delete the old `inc-402` actor so `sre-gateway` creates a fresh actor from the new template. |

## Governed Broker, routing, and zero-trust governance

| Symptom | Cause | Fix |
|---|---|---|
| `sre-gateway` returns `502` / mTLS `403` when dialing `atenet-router` | `atenet-router`'s Envoy RBAC filter does not yet include `spiffe://cluster.local/ns/workshop-301/sa/sre-gateway` (common if Substrate was installed manually without `make patch-router` or shared with Track 101). | Run `make patch-router`. `scripts/patch-router.sh` idempotently merges `spiffe://cluster.local/ns/${NAMESPACE}/sa/sre-gateway` into `atenet-router`'s existing SPIFFE allowlist without removing Track 101's `workshop/gateway` entry. |
| `sre-gateway` logs `403 PermissionDenied` calling Gemini, Model Armor, or Cloud Trace on GKE `1.37` | Clusters with Pod **Agent Identity** enabled authenticate outbound GCP API calls from annotated pods as `principal://agents.global.org-ORG_ID.system.id.goog/...` in addition to `${PROJECT_ID}.svc.id.goog`. IAM bindings can take 60–90 seconds to propagate after `make gcp`. | Re-run `make gcp` (which binds roles to both the Workload Identity principal and the Pod **Agent Identity** principal) and wait 60 seconds. If project model quota is exhausted, run `MOCK_LLM=true make gateway` to continue with deterministic responses (`MOCK_LLM=false make gateway` switches back). |
| `POST /api/incidents/INC-402/remediation/approve` returns `HTTP 401` with `"consent_required": true` | After `make governance` enables `REQUIRE_3LO_FOR_REMEDIATION=true`, remediation merges require a short-lived (`<= 15m`) operator 3LO token in `sre-gateway`'s in-memory vault. Rolling `sre-gateway` or `ops-hub` clears in-memory grants by design. | Click **Authorize 3LO** in the **Incident Console** (`http://localhost:8081/`) and approve access on the Operations Hub consent screen, or run `source scripts/lib.sh && load_env && complete_3lo_pkce_grant http://localhost:8081` in your terminal before re-running the approve request. |
| Browser 3LO consent redirect fails to reach `/api/oauth/callback` in Cloud Shell Web Preview | Your browser opened the Incident Console via a Cloud Shell proxy hostname while `PUBLIC_BASE_URL` pointed at an internal address or stopped port-forward. | Ensure `make forward-gateway` is running when accessing `http://localhost:8081`, or run the headless PKCE helper: `source scripts/lib.sh && load_env && complete_3lo_pkce_grant http://localhost:8081`. |
| `POST /api/chat` returns `HTTP 403` (`MODEL_ARMOR_BLOCKED`) or `/mcp/ops-hub-mcp` returns `HTTP 403` | Expected behavior in Module 05 step 4 when triaging `INC-409` (which embeds an indirect prompt-injection payload) or invoking `destructiveHint: true` tools (`drop_ledger_database`, `delete_production_namespace`). | Switch the incident selector back to `INC-402` or `INC-403` for normal triage, and inspect recorded verdicts in `GET /api/governance` or the **Governance & policy log** tab. |
| `Gateway/sre-ingress-gateway` reports `Programmed: False` (`reason: Invalid`) or returns `HTTP 500` externally | Customizing `GCPAuthzPolicy/sre-ingress-authz-policy` added more than `10` total path matchers across its rules, exceeding Google Cloud Network Security `AuthzPolicy` limits. | Keep total `paths` entries in `modules/05-zero-trust-governance/manifests/ingress-policy.yaml.tmpl` at or below `10` (`make test` enforces this automatically via `scripts/test/governance_test.sh`) and re-apply `make governance`. |
| `curl http://localhost:8081/...` fails with `Connection refused` after `make gateway` or `make governance` | Rolling `Deployment/sre-gateway` replaces the backing Pod and terminates existing `kubectl port-forward` tunnels on port `8081`. | Run `make forward-gateway` to replace the stale port-forward process cleanly. |

## Observability and Online Evals

| Symptom | Cause | Fix |
|---|---|---|
| Cloud Monitoring charts for `sre_gateway_*` metrics are empty right after `make observe` | Managed Service for Prometheus scrapes `PodMonitoring/sre-gateway` every `15s` and takes `1–2` minutes to index initial time series. | Send one chat turn (`INC-403`) so counters increment, verify immediate output via `curl -s http://localhost:8081/metrics \| grep '^sre_gateway_'`, and refresh Cloud Monitoring after `90` seconds. |
| `GET /api/traces/${TRACE_ID}` reports `exported_to_cloud_trace: false` on GKE | Either Cloud Trace IAM (`roles/cloudtrace.agent` and `roles/serviceusage.serviceUsageConsumer`) has not propagated yet, or an explicit `GOOGLE_CLOUD_QUOTA_PROJECT` header was set without Service Usage Consumer permissions. | Re-run `make gcp`, verify `sre_gateway_otel_export_errors_total` on `GET /metrics`, and keep `GOOGLE_CLOUD_QUOTA_PROJECT` unset on Workload Identity and Pod **Agent Identity** deployments so quota bills directly to `projects/${PROJECT_ID}`. |
| `make eval` fails to connect or scores below `0.80` before Module 05 steps run | Either `sre-gateway` is unreachable on `:8081` (though `make eval` opens an ephemeral fallback tunnel on a free local port), or the Module 03 (`REV=v2`), Module 04 (`INC-402` remediation), and Module 05 (`INC-409` Model Armor block) flows have not been executed yet in the current session. | Run `make catch-up MODULE=7` (which replays any missing skill, remediation, governance, or sibling-memory milestones idempotently) and re-run `make eval`. |
