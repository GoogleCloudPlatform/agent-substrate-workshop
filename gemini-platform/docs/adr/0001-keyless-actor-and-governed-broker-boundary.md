# 1. Keyless ADK Go v2 Incident Actor Routed Across a Governed Broker Boundary

Status: accepted

We run the **ADK Go v2** (`google.golang.org/adk/v2`) **Platform SRE Triage Agent** inside an **Agent Substrate (`v1.0.0`)** gVisor **Incident Actor** (`ateworker-gvisor`) with **zero credentials** in environment variables, mounted volumes, or GCS RAM/workspace snapshots, and route all outbound model, session, memory, skill, MCP, SaaS, and telemetry traffic across Substrate `EgressPolicy` through an always-on **Governed Broker** (`Deployment/sre-gateway`).

## Context & Rationale

1. **Why the agent runs inside an Actor**: Investigating production incidents requires cloning repositories into `/workspace`, executing untrusted diagnostic scripts pulled at runtime, running `go test`, staging patches across turns, and suspending to `0 vCPU` / `0 MB RAM` (`< 400ms` GCS restore) while awaiting human remediation approval.
2. **Why GKE governance attaches to `sre-gateway` rather than `WorkerPool`**: Multiplexed `ateworker-gvisor` pods host many Actors over time, block GKE Metadata Server access inside guest sandboxes, tunnel Actor egress via `atunnel` → `atenet-egress`, and are not directly targeted by `GCPAgentGateway` or `app-hub-gke-controller` A2A `Deployment` discovery. Furthermore, fetching OAuth/IAM tokens inside an Actor would persist live bearer tokens into shared GCS RAM snapshots.
3. **Why reverse-proxy broker routes beat bespoke RPCs**: Inside `app/cmd/agent`, participants write idiomatic upstream ADK Go v2 code (`llmagent`, `session.Service` and `memory.Service`, `skilltoolset`, `agentregistry` + `mcptoolset`, `toolconfirmation`, and `otlptracehttp`) pointed at `http://sre-gateway.${NAMESPACE}.svc.cluster.local:8080/{genai,agentengine,agentregistry,mcp,ops,otlp}`. Because ADK Go v2's upstream `memory/vertexai` client dials `<region>-aiplatform.googleapis.com:443` over gRPC with Application Default Credentials, `brokerclient` implements ADK Go v2's `session.Service` and `memory.Service` interfaces over keyless HTTP to `sre-gateway/agentengine/*`, keeping the sandbox completely free of cloud credentials. `sre-gateway` carries Pod **Agent Identity** SPIFFE SVIDs, attaches WIF or **Auth Manager** 3LO credentials on the outbound hop, screens payloads with **Model Armor**, and enforces **Agent Registry** MCP policy outside the sandbox.
